Great content on a slow site doesn't rank. This reality became explicit in 2021 when Google officially added Core Web Vitals as a ranking factor. Before that, technical SEO was often treated as a complement — something you did after getting the content right. Now, server performance, page visual stability during loading, and responsiveness to user interactions are metrics that directly affect search result positions.

But Core Web Vitals are just one layer of technical SEO. There are other equally critical elements that most landing pages ignore: Schema.org for rich snippets, correct canonical tag management for pages with multiple variations, guaranteed crawlability for Googlebot to index correctly, and — when applicable — hreflang for multilingual sites.

## Core Web Vitals: LCP, CLS, and INP in Practice

The three Core Web Vitals measure different dimensions of user experience:

**LCP (Largest Contentful Paint)** measures the time until the largest visible element in the upper fold is rendered. In practice, it's usually the hero image or headline block. The target is below 2.5 seconds.

The most common causes of high LCP in landing pages:

- Hero image in PNG or JPEG format without optimization (use WebP or AVIF)
- Hero image not marked with `fetchpriority="high"` — the browser treats it as a secondary resource
- Third-party CSS or JavaScript blocking rendering before LCP
- No CDN, with the asset being served from the origin server

```html
<!-- Hero image with correct priority -->
<img
  src="/hero.png"
  alt="Image description"
  width="1200"
  height="630"
  fetchpriority="high"
  loading="eager"
/>
```

**CLS (Cumulative Layout Shift)** measures visual instability — elements that move while the page loads. The target is below 0.1.

The biggest CLS culprits are images without defined dimensions (the browser doesn't reserve space before loading), web fonts that cause FOUT (Flash of Unstyled Text), and cookie consent banners that appear after the layout has already been rendered.

**INP (Interaction to Next Paint)** replaced FID in March 2024. It measures response latency to any user interaction (click, tap, key) throughout the entire session. The target is below 200ms. The main cause of high INP is heavy JavaScript on the main thread, especially from analytics libraries and chat widgets.

## Schema.org: Rich Snippets That Boost CTR

Schema.org is a structured data vocabulary that Google uses to understand page content and, in some cases, display rich snippets in search results. Rich snippets increase CTR without directly improving ranking — but more clicks at the same position is a valuable outcome.

For service landing pages, the most relevant schemas are:

```json
{
  "@context": "https://schema.org",
  "@type": "Service",
  "name": "Landing Page Development",
  "description": "Landing pages in Next.js focused on performance and conversion",
  "provider": {
    "@type": "Organization",
    "name": "SystemForge",
    "url": "https://systemforge.dev"
  },
  "areaServed": "US",
  "hasOfferCatalog": {
    "@type": "OfferCatalog",
    "name": "Plans",
    "itemListElement": [
      {
        "@type": "Offer",
        "itemOffered": {
          "@type": "Service",
          "name": "Landing Page Starter"
        },
        "price": "2500",
        "priceCurrency": "USD"
      }
    ]
  }
}
```

For FAQ pages (a common landing page section), the `FAQPage` schema generates display of questions and answers directly in search results, increasing the space occupied in the SERP:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "How long does it take to develop a landing page?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Between 5 and 10 business days depending on complexity and content approval."
      }
    }
  ]
}
```

Validate your implementation with Google's Rich Results Test before publishing.

## Canonical Tags and Duplicate Content

Duplicate content is a frequent problem in landing pages with UTM variations, copy variations for paid vs organic traffic, or versions of the same page on multiple domains.

The canonical tag tells Google which is the "true" URL of a page, consolidating the link equity from all variations into a single URL:

```html
<!-- In all landing page variations -->
<link rel="canonical" href="https://yoursite.com/service-landing-page" />
```

Situations requiring canonical tags in landing pages:

- URLs with UTM parameters being indexed (`/lp?utm_source=google`)
- Same content accessible at `www.yoursite.com` and `yoursite.com`
- Test versions with a different slug than the main version
- Duplicate landing pages for different regions without hreflang configured

The most common mistake is not configuring the canonical tag on pages accessed via UTM parameters. Google doesn't automatically ignore UTM parameters — if the URL with parameters is indexable, it may be interpreted as duplicate content.

## Crawlability: Robots.txt, Sitemap, and Forced Indexing

**Robots.txt** controls which URLs Googlebot can crawl. The classic mistake is accidentally blocking CSS and JavaScript needed to render the page correctly — Google needs to render JavaScript to index SPAs and dynamically rendered pages.

A correct robots.txt for Next.js sites:

```txt
User-agent: *
Allow: /
Disallow: /api/
Disallow: /_next/

Sitemap: https://yoursite.com/sitemap.xml
```

**Sitemap.xml** should list all URLs you want indexed, with the `<priority>` tag adjusted to reflect relative importance. Main landing pages should have priority `1.0`, secondary pages `0.8`, and support pages (privacy policy, terms) `0.3`.

**Forced indexing:** when you publish a new landing page and want Google to index it quickly, use Google Search Console → URL Inspection → Request Indexing. The process takes between hours and 3 days.

The **URL Inspection** tool in Search Console also reveals crawl issues: if Googlebot is encountering redirect errors, if the Googlebot-rendered version differs from what the user sees, or if the canonical tag is being respected.

## Conclusion

Technical SEO is not optional for landing pages that depend on organic traffic. Performance below Core Web Vitals targets, absent structured data, misconfigured canonical tags, and crawlability issues are gaps that the best content in the world can't compensate for.

The advantage of building landing pages with Next.js is that much of this technical SEO comes by default: static export eliminates high TTFB, the `next/image` component automatically resolves LCP and CLS for images, and sitemap generation can be automated.
