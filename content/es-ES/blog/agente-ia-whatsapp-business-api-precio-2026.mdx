Un agente IA custom sobre WhatsApp Business API en Espana 2026 cuesta entre 15.000 y 45.000 euros de implantacion mas 0,02-0,15 euros por conversacion procesada en operacion. ## Por que este articulo NO trata de chatbots

Un chatbot es un flujo de reglas con ramas if-then. Un agente IA con LLM razona sobre la conversacion completa, decide que herramientas usar (consultar pedido, agendar cita, generar factura PDF) y responde con lenguaje natural sin scripts predefinidos. La diferencia practica:

- Chatbot Landbot reconoce 50 frases predefinidas y se rompe en la 51.
- Agente IA con Claude 4.7 entiende variaciones, errores tipograficos, conversaciones que cambian de tema y mantiene contexto a lo largo de 30 mensajes.

Cuando no-code es la respuesta correcta:

- FAQ simples y bien delimitadas
- Volumen menor a 5.000 conversaciones/mes
- Equipo sin perfil tecnico para mantener stack propio
- Presupuesto inicial menor a 3.000 EUR
- Operativa estandar sin integraciones custom

Cuando el no-code se vuelve techo:

- Volumen alto (15.000+ conversaciones/mes) con coste escalado castigando margen
- Necesitas que el bot consulte tu ERP custom en tiempo real
- Quieres RAG sobre catalogo de 10.000 productos o base de conocimiento tecnico
- Operas multi-tenant y revendes el bot bajo tu marca
- Compliance estricto (datos no salen de infra UE)

## Anatomia de un agente IA via WhatsApp Business API

Componentes obligatorios del stack:

### WhatsApp Business API: Meta Cloud o BSP

WhatsApp Business API se accede por dos rutas:

1. **Meta Cloud API directo**: gratis tecnicamente, paga solo conversaciones a Meta. Requiere infraestructura propia para webhooks, tokens, panel admin.
2. **BSP (Business Solution Provider)**: 360dialog, Twilio, MessageBird, MessageBird, Infobip. Anaden capa de gestion (templates, calidad de numero, soporte). Coste mensual base 0-150 EUR + recargo por conversacion 0,005-0,02 EUR.

Para PYME espanola que valora soporte UE y residencia datos: 360dialog (Berlin) es eleccion estandar. Para escala global y stack ya en US: Twilio. Meta directo solo si tienes equipo dev senior y volumen alto que justifique evitar fee BSP.

### Backend que procesa webhooks

Servidor Next.js (Route Handlers) o FastAPI Python recibe el webhook de Meta/BSP cuando llega mensaje, procesa y responde.

### LLM con tool use

El LLM debe soportar tool calling robusto. Recomendaciones 2026:

- **Claude 4.7 Sonnet**: el mejor en tool use complejo, ideal para agentes con 8-15 herramientas.
- **Claude 4.7 Sonnet**: 5x mas barato, suficiente para 80% casos.
- **GPT-5**: paridad funcional con Claude, mejor en algunos benchmarks de razonamiento.
- **Gemini 2.5 Pro**: aceptable, contexto largo (1M tokens) util para conversaciones muy largas.

### Memoria conversacional

Postgres con tabla `conversations` y `messages`, indexada por numero WhatsApp + timestamp. Redis para cache de contexto activo (los ultimos 30 mensajes de la conversacion). El agente recibe historial relevante en cada llamada al LLM, sin tener que reprocesar conversaciones de 6 meses cada vez.

### RAG empresarial

Si el agente debe responder con conocimiento propio (catalogo, documentacion tecnica, manual interno), necesitas RAG. Stack:

- pgvector sobre Postgres si tienes menos de 1M chunks. Mas detalle en [bases de datos vectoriales guia devs IA](/blog/bases-de-datos-vectoriales-guia-devs-ia).
- Qdrant managed o Pinecone si pasas de 1M chunks o quieres escalado distribuido.
- Embedding model: text-embedding-3-large (OpenAI) o voyage-large-2 (Anthropic friendly).

### Tools tipicas del agente

- `consultar_pedido(numero_pedido)`: llama API ERP y devuelve estado.
- `crear_ticket_soporte(asunto, descripcion)`: abre incidencia en Jira/Linear.
- `generar_pdf_factura(numero_factura)`: genera y envia documento.
- `agendar_cita(servicio, fecha, hora)`: integra con Calendly/Google Calendar.
- `escalar_a_humano(motivo)`: notifica equipo y marca conversacion para handoff.
- `consultar_catalogo(query)`: RAG sobre productos o conocimiento.

## Cumplimiento RGPD y consentimiento

Tres reglas no negociables:

1. **Opt-in explicito**: el usuario debe aceptar comunicacion via WhatsApp por escrito antes de cualquier mensaje proactivo. Caja registrada en BD con timestamp y origen.
2. **Politica privacidad accesible**: link visible en primer mensaje del bot, mencion de uso de IA y proveedor (Anthropic/OpenAI).
3. **Logs LLM con minimizacion**: no almacenes contenido completo si no es estrictamente necesario. Logs de metadata + outcome bastan en muchos casos.
4. **Derecho al olvido**: procedimiento tecnico documentado (borra conversaciones + memoria + entrada vector DB) ejecutable en 30 dias.

AI Act 2026 clasifica chatbot/agente como sistema de riesgo limitado: transparencia obligatoria (el usuario sabe que habla con IA), no se puede usar IA para manipulacion subliminal o explotacion de vulnerabilidades. ## Como implantar en 6 semanas

Plan probado en 4 proyectos:

- **Semana 1-2**: setup BSP + numero WhatsApp Business + webhook + estructura Next.js + conexion LLM con prompt base. Bot "hola mundo" funcional.
- **Semana 3**: implementar 3-5 tools clave (consultar pedido, escalar humano, FAQ). Pruebas en sandbox.
- **Semana 4**: ingesta de documentos en RAG + casos de uso reales en testing dirigido.
- **Semana 5**: cola humana fallback + panel admin + observabilidad. Pruebas con 5-10 usuarios beta.
- **Semana 6**: piloto produccion (10% trafico real) + ajuste umbrales confianza + handoff. Lanzamiento total cuando metricas estables 5 dias.

## Errores comunes

Lista de fallos que se repiten:

1. **Sin fallback humano**: el LLM no puede resolver todo. Cuando confianza es baja o usuario pide humano explicitamente, debe escalar limpio. Sin esto, cliente furioso garantizado.
2. **Templates marketing sin opt-in valido**: Meta banea numeros que envian marketing a usuarios que no aceptaron. Caso real: cliente perdio numero y BSP por enviar promo a base "cargada" sin consentimiento.
3. **LLM sin guardrails**: el agente inventa precios, promete descuentos, comparte info de otros clientes. Necesitas system prompt robusto y validacion outputs.
4. **Sin cache de prompt**: enviar 8.000 tokens de system prompt en cada mensaje cuesta x3 lo que deberia. Anthropic prompt caching ahorra 90% de eso.
5. **Sin observabilidad**: cuando algo falla en produccion no sabes que prompt fue, que tools se llamaron, por que el LLM eligio responder asi. Langfuse o Helicone son obligatorios.
6. **Webhook sin validacion firma**: Meta firma cada webhook con HMAC. Si no validas, cualquiera puede enviar mensajes falsos a tu sistema.
7. **Olvidar el coste cuando volumen explota**: lanzar a 5K convs/mes y al mes 4 ya estas en 30K sin haber recalculado coste API. Alarmas de presupuesto en LangFuse/Helicone obligatorias.

## FAQ

**Cuando merece la pena migrar de Landbot a custom?**
Cuando 1) volumen mensual supera 15.000 conversaciones consistentemente y el coste mensual Landbot/Botmaker pasa de 600 EUR/mes, 2) necesitas funcionalidad que el no-code no soporta (RAG sobre catalogo grande, tool use complejo con tu ERP), 3) clientes B2B exigen residencia datos UE estricta o auditoria, 4) tu modelo de negocio incluye revender el bot a tus propios clientes con marca propia. Sin alguna de estas, sigue en Landbot.

**Meta puede banear mi numero si uso LLM?**
Si, si violas politicas Meta (spam, marketing sin opt-in, contenido prohibido). El LLM no es violacion per se. Lo que banea es enviar mensajes que generen quejas (rate de quejas mayor al 8% durante 7 dias) o usar templates aprobados para fines distintos. Tu agente debe tener guardrails que eviten esto. Tener BSP ayuda porque te avisan antes de que llegues al limite.

**Necesito BSP o puedo usar Cloud API directo de Meta?**
Tecnicamente Cloud API directo es viable. Meta cobra solo conversaciones, BSP cobra extra. Pero BSP te da: panel admin para gestion templates, soporte cuando hay incidencia, mejor calidad de numero (BSP gestiona quality rating), residencia datos en UE garantizada (360dialog Berlin). Para PYME sin equipo dev senior dedicado: BSP. Para empresa con equipo dev fuerte y volumen alto justificando: directo.

**Cuanto tarda el agente custom en responder?**
Latencia tipica 2-5 segundos para respuesta simple sin tool calls. 4-10 segundos si llama 1-2 tools (consulta ERP). 10-20 segundos si hace RAG + multiples tools. WhatsApp tolera estos tiempos sin problema; usuarios estan acostumbrados a chats con humanos que tardan minutos. Si necesitas respuesta inferior a 2s, optimiza con cache de respuestas frecuentes y prompt caching.

**Puedo usar el mismo numero para humano y bot?**
Si, con handoff bien implementado. El bot atiende por defecto, cuando detecta caso para humano (palabra clave, baja confianza, peticion explicita) marca la conversacion para que un agente humano la coja desde panel inbox. Stack: tu panel admin custom o herramientas como Chatwoot, Front, Crisp con API WhatsApp.

**Funciona offline con LLM local?**
Tecnicamente si: Llama 3.3 70B o Mistral Large self-hosted en GPU. Pero coste hardware (2-4 GPUs A100, 25.000-50.000 EUR setup + 800-1.500 EUR/mes electricidad y mantenimiento) solo se justifica con volumen muy alto, datos extremadamente sensibles o requisito legal estricto. Para 99% de casos, LLM cloud en region UE cumple y es 10x mas barato.
