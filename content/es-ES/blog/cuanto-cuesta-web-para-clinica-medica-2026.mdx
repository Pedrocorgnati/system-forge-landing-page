## Qué diferencia una web médica de una web empresarial estándar

Una web para clínica no es simplemente un sitio bonito con un formulario de contacto. Hay tres capas de exigencias específicas que aumentan el coste y que muchos proveedores económicos ignoran — hasta que aparecen los problemas.

### 1. Normativa de publicidad sanitaria en España

La Ley 34/1988 General de Publicidad y las circulares del Consejo General de Colegios Médicos establecen reglas específicas para la comunicación sanitaria online. Esto afecta directamente a lo que puede y no puede aparecer en la web:

- **Prohibido:** promesas de resultados o curación, comparativas con otros profesionales o clínicas, uso de testimonios que induzcan a error sobre resultados típicos
- **Obligatorio:** número de colegiado visible, especialidades reconhecidas por el Colegio indicadas correctamente, identificación clara de si la clínica es privada o concertada con la Seguridad Social
- **Atención especial:** páginas de procedimientos estéticos, cirugía plástica y terapias alternativas tienen restricciones más estrictas

Un desarrollador que desconoce estas normas entrega una web que puede resultar en una denuncia al Colegio de Médicos.

### 2. RGPD para datos de salud

Los datos de salud son datos especiales bajo el RGPD (Art. 9) y requieren medidas de protección más estrictas que los datos ordinarios. Un formulario de cita que recoge nombre, teléfono y motivo de la consulta ya constituye tratamiento de datos potencialmente sensibles.

La web necesita: política de privacidad específica para datos sanitarios, base jurídica clara (consentimiento explícito para datos de salud), mecanismo de retirada del consentimiento, y — si hay portal del paciente — cifrado obligatorio de los datos tanto en tránsito como en reposo.

### 3. Integración con sistemas de citas

Las clínicas utilizan sistemas como Doctoralia, Doctolib, iClinic, Medigest, o el módulo de citas de su software clínico (Salud Dictus, Gestlab, etc.). Una web con cita online debe conectarse al sistema que la clínica ya usa — de lo contrario, la cita se convierte en un proceso duplicado que genera más confusión que la que resuelve.

Las integraciones vía API con estos sistemas añaden €1.200–€4.000 al proyecto según la API disponible y la complejidad.

## Cuánto cobra cada tipo de proveedor

**Freelance junior (€800–€3.000):** Entrega una web en WordPress o Wix, sin integración real de citas, sin conocimiento de la normativa de publicidad sanitaria, con política de privacidad genérica no conforme al RGPD sanitario. Para una clínica que solo quiere presencia online básica, puede funcionar. Para cualquier cosa más, es un riesgo legal y reputacional.

**Agencia de marketing digital (€4.000–€15.000):** Hace webs con enfoque en diseño y SEO. Pocas tienen experiencia específica en conformidad sanitaria o integraciones con software clínico. Pide referencias de otros proyectos en el sector salud antes de contratar.

**Software house especializada (€7.000–€35.000):** Entrega el proyecto completo con conformidad normativa, RGPD adecuado, integración real de citas y soporte técnico. Coste mayor, pero única opción segura para clínicas con volumen real de pacientes y responsabilidad profesional.

**Plataformas específicas del sector (Doctoralia, Doctolib — €80–€300/mes):** Solución SaaS con web pre-formateada + citas incluidas. Buena para consultas pequeñas que quieren simplicidad. Limitada en personalización e identidad de marca.

## Qué incluye una web completa para clínica médica

**Páginas obligatorias:**
- Inicio con especialidades, servicios y CTA de cita claro
- Quiénes somos con currículum del médico y número de colegiado
- Página por especialidad (cada especialidad merece URL propia para SEO local)
- Cita online o enlace directo al sistema de citas
- Contacto con Google Maps y horarios
- Aviso legal, política de privacidad y cookies (RGPD)

**Requisitos técnicos:**
- Integración con Google Business Profile
- Schema markup LocalBusiness y MedicalOrganization
- Certificado SSL (HTTPS) — obligatorio para cualquier web que recoja datos
- Velocidad de carga inferior a 3 segundos en móvil (Core Web Vitals)
- Accesibilidad WCAG 2.1 AA (exigida para entidades que reciben subvención pública y recomendada para todas)

**Para clínicas más grandes:**
- Blog médico con contenido de autoridad (SEO a largo plazo)
- Telemedicina integrada (conforme a la Ley 41/2002 y normativa autonómica)
- Portal del paciente con área privada y resultados de pruebas

## FAQ — Web para Clínica Médica

**¿La web de una clínica médica necesita aviso de cookies específico?**
Sí. La Agencia Española de Protección de Datos (AEPD) tiene directrices específicas sobre el banner de cookies. Debe ser conforme: sin pre-consentimiento, aceptar y rechazar igualmente accesibles, granularidad por categoría de cookie. Las soluciones genéricas no son suficientes — se requiere una herramienta de gestión del consentimiento conforme (Cookiebot, Iubenda, OneTrust).

**WordPress o desarrollo personalizado para una clínica?**
Para la mayoría de las clínicas, WordPress con un tema médico premium funciona bien a menor coste. El desarrollo personalizado (Next.js, React) tiene sentido para: portales de pacientes con autenticación compleja, clínicas con alto tráfico, o necesidades de integración con software clínico no manejables con plugins de WordPress.

**¿Cuánto tiempo tarda en aparecer en Google?**
Los resultados SEO orgánicos suelen tardar 3–6 meses. Para visibilidad más rápida en búsquedas locales (p. ej., "dermatólogo Madrid"), Google Ads locales y un perfil de Google Business Profile optimizado son más efectivos a corto plazo.

**¿Puedo usar testimonios de pacientes en la web?**
Los testimonios de pacientes que expresen resultados clínicos están muy limitados por la normativa de publicidad sanitaria y el Código de Deontología Médica. Las valoraciones en plataformas de terceros (Google Business, Doctoralia) se tratan de forma diferente, pero siguen siendo un área a gestionar con precaución.

**¿Cuál es el presupuesto mínimo para una web médica profesional?**
€3.000–€4.500 es el mínimo para tener una web que: funcione bien en móvil, tenga buena velocidad, sea segura (HTTPS), tenga SEO básico configurado, sea conforme al RGPD con política de privacidad correcta, e incluya un formulario de contacto funcional.
