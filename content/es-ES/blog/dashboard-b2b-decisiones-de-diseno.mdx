Un dashboard B2B que nadie usa es, en el mejor caso, dinero malgastado y, en el peor, un obstáculo activo — el equipo evita usarlo y crea workarounds en Excel que producen datos inconsistentes. El problema raramente está en la tecnología. Está en las decisiones de diseño que determinan si el dashboard responde a las preguntas reales del usuario o a lo que el equipo de producto pensó que serían sus preguntas.

Estas son las 10 decisiones de diseño más frecuentes en dashboards B2B — con las opciones correctas e incorrectas para cada una.

## 1. ¿Qué métricas aparecen en el header?

El error más común: mostrar todas las métricas disponibles porque "el usuario puede decidir cuáles le importan". No puede — o mejor dicho, no debería tener que hacerlo. Un dashboard bien diseñado ya hizo esa priorización.

**Correcto:** 4-6 KPIs principales que el usuario revisa cada vez que entra, con tendencia respecto al período anterior. Ejemplo para un dashboard de ventas: MRR actual, clientes activos, tasa de conversión del mes, churn del mes.

**Incorrecto:** 20 métricas en el header con la misma jerarquía visual.

## 2. Filtros: ¿Globales o por Módulo?

Si el dashboard tiene múltiples secciones (ventas, marketing, operaciones), ¿el filtro de fecha aplica a todo o a cada sección por separado?

**Correcto:** Filtro de período global en el header que afecta a todo el dashboard simultáneamente. Cada sección puede tener filtros adicionales específicos (por región, por producto) pero el período es siempre global.

**Incorrecto:** Cada sección con su propio filtro de fecha independiente — el usuario no puede comparar datos del mismo período entre secciones.

## 3. Tabla vs Gráfico: Cuándo Usar Cada Uno

Las tablas son para búsqueda y comparación entre muchos items. Los gráficos son para tendencias y comparaciones entre pocas series. Mezclarlos incorrectamente genera confusión.

- Evolución del MRR en 12 meses → Gráfico de líneas
- Lista de los 20 clientes con mayor ARR → Tabla con ordenación
- Distribución de clientes por plan → Gráfico de barras o pie
- Desglose de facturas por cliente → Tabla exportable

## 4. Tablas Largas: Paginación vs Scroll Infinito vs Virtual Scroll

Para tablas con cientos o miles de filas:

- **Paginación:** Más predecible, más fácil de retomar una posición. Mejor para tablas donde el usuario busca un item específico.
- **Scroll infinito:** Mejor para exploración continua (feed de actividad, log de eventos). Problemático para volver a una posición específica.
- **Virtual scroll (solo renderiza las filas visibles):** La opción técnica correcta para listas de 10.000+ filas sin impacto en rendimiento.

## 5. Exportación: ¿Qué Formato y Cuándo?

Los usuarios de dashboards B2B siempre quieren exportar. No hay que convencerlos — hay que hacerlo fácil.

**Formatos esenciales:**
- CSV: Para análisis en Excel/Google Sheets (el más solicitado)
- Excel (.xlsx): Para usuarios que quieren formateo preservado
- PDF: Para informes que se envían por email

La exportación debe reflejar los filtros activos — no exportar todos los datos, sino los datos que el usuario está viendo en ese momento.

## 6. Fechas: Presets vs Rangos Libres

El selector de período es una de las interacciones más frecuentes. Los presets (Hoy, Esta semana, Este mes, Este trimestre, Este año, Últimos 30 días) cubren el 90% de los casos. El rango libre es para el 10% restante.

El error es mostrar solo el rango libre — obliga al usuario a calcular y escribir fechas para casos que deberían ser un clic.

## 7. Tiempo Real vs Actualización Periódica

No todos los dashboards necesitan datos en tiempo real. Los websockets tienen coste de infraestructura y complejidad técnica. La pregunta correcta: ¿el usuario toma decisiones en un plazo de minutos o de horas/días?

- **Tiempo real (WebSocket):** Panel de operaciones de una plataforma de e-commerce durante el Black Friday, monitorización de servidores, seguimiento de repartidores
- **Actualización cada 5 minutos:** Dashboard de ventas del día, métricas de SaaS
- **Actualización diaria:** Informes de negocio, análisis de tendencias

## 8. Estado Vacío: El Diseño Olvidado

Un dashboard sin datos — porque el cliente es nuevo o porque los filtros no devuelven resultados — muestra un estado vacío. La mayoría de los dashboards muestra pantallas en blanco o textos genéricos de "No hay datos".

El estado vacío bien diseñado explica por qué está vacío y qué acción puede tomar el usuario para llenarlo.

## 9. Mobile: ¿Responsivo o App Separada?

Los dashboards B2B se usan principalmente en desktop. Pero "consulta rápida en el móvil" es un caso de uso real — el director general revisa el MRR desde el teléfono.

La solución pragmática: diseño responsive donde las métricas principales son accesibles en móvil y las tablas complejas tienen un fallback de "Ver en desktop para la tabla completa". No intentes meter el dashboard completo en una pantalla de 375px.

## 10. Tooltips y Definiciones: Evitar la Ambigüedad

"Usuarios activos" puede significar cosas distintas para personas distintas. ¿Es activo quien entró esta semana? ¿Este mes? ¿Quien completó una acción específica?

Cada métrica debe tener un tooltip con la definición exacta y el período que cubre. Este detalle — que tarda 5 minutos en implementar — evita conversaciones confusas en reuniones de revisión y decisiones basadas en malentendidos.

## Conclusión

Un dashboard B2B bien diseñado no es una colección de gráficos — es una respuesta a las preguntas reales que el usuario necesita responder cada día. Las 10 decisiones anteriores determinan si el dashboard facilita esas respuestas o las complica.
