# Por qué tu empresa necesita un contrato de mantenimiento de software — y qué pasa cuando no lo tiene

*Por Pedro Corgnati, Fundador de SystemForge — desarrollador de sistemas a medida y especialista en modernización de software para PYMEs.*

**Tu empresa necesita un contrato de mantenimiento de software porque todo sistema envejece: las dependencias quedan obsoletas, surgen vulnerabilidades de seguridad, las integraciones con APIs externas se rompen y nuevos requisitos normativos (como cambios en la facturación electrónica o en la protección de datos) exigen actualizaciones urgentes.** Sin un contrato formal, cada problema se convierte en una negociación de emergencia con coste imprevisible. Un contrato de mantenimiento bien estructurado cuesta entre 500€ y 4.000€/mes para sistemas de PYME y evita pérdidas que, en la práctica, llegan a multiplicar por 10 ese valor cuando el sistema falla en el momento equivocado.

Esta guía explica qué debe incluir un contrato de mantenimiento, qué modelos existen, cuánto cuestan y cómo evaluar si lo que tienes hoy es suficiente.

## Mantenimiento de software vs. soporte técnico: la diferencia

**Soporte técnico** atiende problemas de uso: el usuario no sabe usar una función, olvidó la contraseña, tuvo un error puntual. Es reactivo.

**Mantenimiento de software** es el trabajo técnico que mantiene el sistema funcionando y seguro a lo largo del tiempo: actualizar dependencias, corregir bugs, adaptar el código a cambios en APIs externas, ajustar el sistema a nuevos requisitos normativos, optimizar el rendimiento cuando el volumen crece.

Los cuatro tipos de mantenimiento reconocidos en la ingeniería de software:

- **Correctivo:** corrige bugs y errores en producción
- **Adaptativo:** adapta el sistema a cambios en el entorno (nuevo SO, nueva versión de base de datos, cambio de API externa)
- **Perfectivo:** mejora el sistema con nuevas funcionalidades u optimizaciones de rendimiento
- **Preventivo:** refactoriza el código antes de que se convierta en problema, actualiza dependencias antes de que queden obsoletas

## Qué pasa con un sistema sin mantenimiento

**Meses 1-6 tras el fin del mantenimiento:** nada perceptible.

**Meses 6-18:** aparecen las primeras grietas. Una integración con la pasarela de pagos que cambió su API, un informe que tarda 3 veces más porque la base de datos acumuló datos sin indexación, una funcionalidad que deja de funcionar tras una actualización del servidor.

**Año 2-3:** el sistema está técnicamente desfasado. Las bibliotecas que utiliza tienen versiones vulnerables. Cualquier desarrollador nuevo tardará semanas en entender el código porque no hay documentación actualizada.

**Año 3+:** el sistema se convierte en un "sistema legacy crítico." Nadie quiere tocarlo por miedo a romper algo. La empresa queda como rehén del sistema y del desarrollador original. El coste de modernización ahora es 3-5 veces el que habría supuesto un mantenimiento continuo.

## Qué debe incluir un contrato de mantenimiento de software

**1. Alcance de servicios:** qué está incluido. ¿Mantenimiento correctivo (bugs)? ¿Adaptativo (integraciones)? ¿Perfectivo (mejoras)? ¿Preventivo (actualizaciones de seguridad)?

**2. SLA (Service Level Agreement):** plazos de respuesta y resolución por tipo de incidente. Un sistema crítico parado merece respuesta en 1-2 horas. Un bug que afecta al 5% de los usuarios puede tener plazo de 3 días hábiles.

**3. Horas incluidas y cómo se consumen:** los contratos mensuales incluyen habitualmente un número de horas. ¿Cómo se registran? ¿Qué pasa con las horas no utilizadas? ¿Cuál es el precio de la hora adicional?

**4. Responsabilidades de cada parte:** tú eres responsable de mantener los accesos actualizados y aprobar los despliegues. El proveedor es responsable de documentar el trabajo realizado y mantener las copias de seguridad.

**5. Confidencialidad y propiedad del código:** ¿el código desarrollado y mantenido es tuyo? ¿O pertenece al proveedor? El contrato debe ser explícito. Incluir cláusulas de RGPD es obligatorio si el sistema trata datos personales.

**6. Criterios de rescisión y transición:** si el contrato se rescinde, ¿cómo se realiza el traspaso? Entrega del código fuente, documentación, credenciales y formación.

## Modelos de contrato y rangos de precio

| Modelo | Qué incluye | Rango mensual | Ideal para |
|---|---|---|---|
| Horas a consumo | Bolsa de horas sin compromiso mensual | 80-130€/h | Sistemas simples, baja demanda |
| Retainer fijo — correctivo | X horas/mes para corrección de bugs y soporte | 600-2.000€/mes | Sistemas estables, pocos usuarios |
| Retainer completo — 4 tipos | Correctivo + adaptativo + preventivo + reunión mensual | 1.500-4.000€/mes | Sistemas de negocio críticos |
| Managed maintenance | SLA 4h, on-call, monitorización 24/7, informes mensuales | 4.000-12.000€/mes | E-commerce, sistemas financieros, SaaS |

## Cómo evaluar si tu contrato actual es suficiente

Hazte estas preguntas sobre tu contrato actual:

1. Si el sistema se cae ahora, ¿qué tiempo de respuesta está garantizado por escrito?
2. ¿Las actualizaciones de seguridad de las bibliotecas están incluidas? ¿Con qué frecuencia se realizan?
3. ¿Tienes acceso al código fuente y puedes llevarlo a otro proveedor si quieres?
4. ¿El contrato prevé adaptaciones a cambios normativos (factura electrónica, RGPD)?
5. ¿Cómo se documentan las horas trabajadas?
6. Si rescindas, ¿cómo se realiza el traspaso?

Si no puedes responder a tres o más de estas preguntas, hay lagunas que pueden salir caras.

## El coste real de no tener mantenimiento

- **Sistema caído 8 horas en período pico:** 10.000-60.000€ en ventas perdidas (e-commerce), más el coste de emergencia para resolverlo.
- **Brecha de datos por vulnerabilidad no parcheada:** multa RGPD de hasta 20 millones de euros o el 4% de la facturación mundial anual (la cifra mayor de las dos).
- **Refactorización de un sistema sin documentación tras 3 años sin mantenimiento:** 60-80% del coste de desarrollo original.

En comparación, un contrato de mantenimiento de 2.000€/mes cuesta 24.000€/año, menos que una sola emergencia grave.

## Preguntas frecuentes

### ¿Cuál es la diferencia entre contrato de mantenimiento y garantía del sistema?

La garantía cubre bugs existentes en el momento de la entrega (normalmente 90 días tras el go-live). El contrato de mantenimiento cubre todo lo que ocurre después: nuevos bugs en producción, cambios de entorno, integraciones que se rompen por cambios externos.

### ¿Puedo contratar el mantenimiento con un proveedor diferente al que desarrolló el sistema?

Sí, pero requiere la entrega completa del código fuente, la documentación y las credenciales de acceso. Si el proveedor original no entregó esto, estás en una posición vulnerable.

### ¿Cuántas horas mensuales son suficientes para un sistema de PYME?

Para sistemas de gestión interna de PYME (ERP ligero, CRM, sistema de citas), 10-20 horas/mes de mantenimiento preventivo + correctivo son una referencia razonable. Para sistemas de e-commerce o SaaS con múltiples integraciones, el mínimo sube a 30-50 horas/mes.

### ¿Qué es un SLA y por qué importa en el contrato?

El SLA es el plazo contractual de respuesta y resolución de incidentes. Sin SLA, dependes de la buena voluntad del proveedor en emergencias. Con SLA, hay una penalización si el plazo no se cumple.

### ¿Un sistema en la nube necesita contrato de mantenimiento?

Sí. Los sistemas en la nube (AWS, Azure, GCP, Vercel) siguen necesitando mantenimiento del código: actualizaciones de dependencias, ajustes de configuración, optimización del rendimiento.
