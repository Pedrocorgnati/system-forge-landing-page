# Modelos de Precios para SaaS en 2026: cómo definir y probar el precio correcto

Un pricing incorrecto hunde los SaaS lentamente. Una empresa puede lanzar el producto correcto, con el equipo correcto, para el cliente correcto — y tener igualmente un churn alto porque el modelo de precios no refleja el valor que el cliente percibe. En 2026 los cinco modelos principales de SaaS son: por usuario (per-seat), por uso (usage-based), tiers/paquetes, freemium y tarifa plana. Cada uno funciona en contextos específicos y destruye ingresos en otros. La tasa de conversión mediana de trial a pagante en B2B SaaS es del 15–25%; de freemium a pagante, del 2–5%. Estos números cambian drásticamente según el modelo de precios elegido.

Soy Pedro Corgnati, fundador de SystemForge. He construido y lanzado SaaS para PYMEs españolas y europeas durante los últimos 6 años. Este artículo combina lo que he aprendido en la práctica con datos de mercado de 2026.

## Los 5 modelos de pricing y cuándo usar cada uno

### 1. Por usuario (Per-seat)

**Cómo funciona:** el cliente paga por usuario activo en el sistema. Ej.: €39/mes por usuario.

**Cuándo usar:** productos de colaboración donde el valor crece con el número de usuarios activos (Slack, GitHub, herramientas de gestión de proyectos). Precio predecible para el cliente, ingresos predecibles para ti.

**Cuándo no usar:** productos donde el ROI no crece con más usuarios (herramientas de análisis, procesadores de datos en batch). En ese caso, añadir un usuario no genera más valor — el cliente resiste el aumento de factura.

**Consideración para PYMEs españolas:** muchas PYMEs tienen 2–5 usuarios. Un precio por usuario alto genera fricción en la expansión. Incluye los primeros 3 usuarios en el plan base.

### 2. Por uso (Usage-based)

**Cómo funciona:** el cliente paga por lo que consume. Ej.: €0.12 por transacción procesada, €8 por 1 000 emails enviados, €0.002 por token de IA procesado.

**Cuándo usar:** cuando el valor del producto está directamente ligado al volumen de uso — APIs, herramientas de comunicación, procesamiento de datos, IA generativa. Baja barrera de entrada.

**Cuándo no usar:** cuando el cliente necesita predictibilidad de costes para aprobar el presupuesto. Un CFO no aprueba "paga lo que uses" sin un tope. Solución: usage-based con tope mensual o tier mínimo.

**Modelo híbrido 2026:** base mensual (ej: €79/mes) + uso por encima de un umbral (ej: las primeras 1 000 transacciones incluidas, luego €0.06/transacción).

### 3. Tiers/Paquetes

**Cómo funciona:** 2–4 paquetes con funcionalidades diferentes. Ej.: Starter €59/mes, Pro €149/mes, Business €399/mes.

**Cuándo usar:** la mayoría de los SaaS B2B. Permite adquirir clientes a un precio menor y expandir ingresos sin un nuevo ciclo de venta (upgrade de Starter a Pro cuando el cliente crece).

**Diseño de los tiers:** el tier del medio (Pro) debe tener el mayor margen y el mayor volumen de clientes. El tier de entrada debe tener suficiente para que el cliente perciba valor pero crear fricción natural hacia el upgrade.

**Error clásico:** crear tiers por número de usuarios cuando el diferencial de valor está en las funcionalidades.

### 4. Freemium

**Cómo funciona:** versión gratuita permanente con limitaciones + versión de pago completa.

**Cuándo usar:** producto con PLG (Product-Led Growth) real. Requiere una gran base de usuarios para tener conversión relevante. Funciona mejor cuando el freemium crea efectos de red.

**Cuándo no usar:** SaaS B2B con ciclo de venta largo, donde el coste de soporte/infraestructura del tier gratuito no está cubierto por la conversión.

**Alternativa al freemium:** prueba gratuita con tiempo limitado (14–30 días, tarjeta obligatoria) convierte 3–5x mejor que el freemium permanente para B2B.

### 5. Tarifa plana (Flat-rate)

**Cómo funciona:** un precio fijo al mes, todos los usuarios y funcionalidades incluidas.

**Cuándo usar:** producto con propuesta de valor clara y base de clientes homogénea. Simple, fácil de comunicar.

**Cuándo no usar:** cuando tu base va desde PYME pequeña a empresa grande. La tarifa plana te fuerza a prezzar para el cliente más pequeño (pierdes margen en los grandes) o para el más grande (imposible la entrada de los pequeños).

## Cómo elegir el modelo correcto

Responde estas 4 preguntas antes de decidir:

1. **¿Qué define el valor para el cliente?** Número de usuarios → per-seat. Volumen procesado → usage-based. Funcionalidades disponibles → tiers.
2. **¿Quién aprueba el presupuesto?** CEO/dueño de PYME → predictibilidad, prefiere tiers. CFO de empresa mayor → acepta usage con tope. Dev individual → freemium/trial.
3. **¿Cuál es el coste variable por cliente?** Si el coste de infraestructura crece con el uso, usage-based distribuye esa carga.
4. **¿Cuál es el motion de crecimiento?** PLG (usuario recluta usuario) → freemium. Sales-led (ciclo de ventas activo) → tiers o tarifa plana con demo.

## Cómo testear pricing con Stripe antes de comprometerse

```typescript
// Stripe con dos Price IDs distintos para test A/B
const priceId = userGroup === 'A'
  ? 'price_1ABC...per_seat_79'    // Grupo A: €79/usuario
  : 'price_1XYZ...flat_149'       // Grupo B: €149 tarifa plana

const session = await stripe.checkout.sessions.create({
  mode: 'subscription',
  line_items: [{ price: priceId, quantity: 1 }],
  success_url: `${baseUrl}/dashboard?session_id={CHECKOUT_SESSION_ID}`,
  cancel_url: `${baseUrl}/pricing`,
})
```

Divide los nuevos usuarios aleatoriamente (50/50 o 70/30) entre los grupos. Mide tras 30–60 días: tasa de conversión (gratis → pagante), MRR por cliente, churn en el primer mes.

## FAQ

**¿Debo cobrar en euros o dejar abierta la posibilidad de cobrar en otras monedas?**

Para un producto enfocado en España: euros. Para productos con clientes internacionales desde el lanzamiento, considera el multicurrency desde el principio (Stripe lo soporta nativamente). El desajuste de divisas — compradores españoles esperando EUR pero viendo USD — genera fricción y churn.

**¿Qué precio poner en el lanzamiento: bajo para conseguir clientes o justo para tener margen?**

La regla práctica: precio según el valor generado, no según el coste. Si tu SaaS ahorra al cliente €3 000/mes en retrabajo, cobrar €199/mes es demasiado barato (y señala inseguridad). Empieza por el precio que crees que es justo. Subir precios después es mucho más difícil que hacer un descuento para cerrar un deal concreto.

**¿Cómo estructurar el tier Enterprise sin comprometerse a un precio fijo?**

Enterprise con pricing personalizado: no muestres precio en el sitio para el tier Enterprise ("Contáctanos"). Incluye: SLA contractual, integración SSO/SAML, datos en servidor dedicado, formación y onboarding, Account Manager dedicado. Negociado anualmente con anticipo de ingresos.

**¿Vale la pena tener prueba gratuita sin tarjeta obligatoria?**

Para B2B, no — en 2026. La prueba sin tarjeta genera más registros pero convierte mucho menos (1–3% vs 8–15% con tarjeta). La mejor práctica actual para B2B: prueba 14 días con tarjeta obligatoria + cancelación automática si no convierte + emails de onboarding agresivos en los primeros 3 días.

**¿Cuándo tiene sentido cambiar el modelo de pricing con clientes ya activos?**

Cuando el churn es alto y el patrón de cancelación indica desalineamiento de valor. El cambio de modelo con clientes activos requiere: grandfathering (los clientes existentes se quedan al precio antiguo durante 12–24 meses), comunicación con 60–90 días de antelación, migración por cohortes empezando por los nuevos clientes.
