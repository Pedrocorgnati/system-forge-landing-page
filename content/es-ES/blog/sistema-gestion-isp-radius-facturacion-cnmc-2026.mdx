# Sistema de Gestión para ISP en 2026: RADIUS, Facturación, CNMC y Coste para Operadores Regionales

Un sistema de gestión propio para un ISP regional español cuesta **28.000–110.000 €** en 2026, más 500–2.000 €/mes de infraestructura. El sistema integra facturación (SDD SEPA, tarjeta, domiciliación bancaria), autenticación RADIUS (FreeRADIUS o Mikrotik RouterOS API), factura electrónica FacturaE/VeriFactu, reporting de calidad CNMC, suspensión automática de morosos y portal de autogestión para clientes. Las plataformas comerciales internacionales no cubren correctamente la normativa española — FacturaE con firma XAdES, VeriFactu, portabilidad de dominio CNMC — y un operador regional que las adopta acaba manteniendo dos sistemas en paralelo.

## Qué Debe Hacer un Sistema de Gestión ISP

Cinco áreas cubren el alcance funcional completo:

### Facturación y Gestión de Morosidad

**SDD SEPA** (SEPA Direct Debit) es el método principal para ISP españoles con contratos residenciales recurrentes. El sistema almacena el identificador de acreedor (obtenido del banco), gestiona los mandatos firmados digitalmente al alta del cliente, genera los ficheros XML ISO 20022 (PAIN.008) para la presentación bancaria, y procesa los riesgos devueltos R-transaction (R03 cuenta cancelada, R08 fondos insuficientes, R13 número de cuenta inválido) con flujos de recuperación diferenciados.

**Tarjeta de crédito recorrente.** Stripe o Redsys para clientes empresariales que prefieren cargo en tarjeta. Tasa de morosidad estructuralmente menor que el SDD para clientes de empresa — el cargo en tarjeta tiene ciclo de pago más predecible. Los dos métodos coexisten en el mismo sistema, con lógica de reintento automática independiente.

**Suspensión gradual por morosidad.** En vencimiento + 3 días: reducción de ancho de banda a 512Kbps (con aviso por email y SMS). En +7 días: redirección a portal cautivo con enlace de pago. En +14 días: suspensión completa vía API Mikrotik o atributo RADIUS. La reactivación es inmediata al confirmar el pago vía webhook bancario — cero intervención manual. Para ISP con 500+ clientes gestionados manualmente, esta automatización sola justifica el coste de desarrollo.

### Integración RADIUS

**FreeRADIUS** es la solución open-source más usada para autenticación PPPoE en ISP con infraestructura heterogénea. El sistema propio interactúa vía backend SQL (FreeRADIUS lee auth/accounting desde MariaDB o PostgreSQL compartido) — más rápido de implementar y mantener que la integración directa vía protocolo RADIUS.

Operaciones clave:
- **Autenticación**: cuando el cliente conecta PPPoE, FreeRADIUS consulta la base de datos para username/password y atributos de respuesta (perfil de velocidad, asignación IP)
- **Accounting**: registros start/stop/interim escritos en las tablas de accounting — fuente de verdad para datos de consumo y uptime
- **Suspensión**: inserción/eliminación de registro `radreply` para cambiar atributos de respuesta (throttle, redirect portal cautivo)

**Mikrotik RouterOS API** (puerto 8728 TCP) para ISP que usan Mikrotik como gateway PPPoE. Llamadas API directas para crear/modificar perfiles PPPoE, aplicar Queue Tree para QoS por cliente, y consultar sesiones activas. Más granular que RADIUS para operaciones en tiempo real — la suspensión vía API Mikrotik es inmediata, no espera el siguiente re-auth PPPoE.

### Factura Electrónica (FacturaE y VeriFactu)

**FacturaE** es el formato XML obligatorio para facturación electrónica B2B en España (Ley 25/2013 para administraciones públicas; extensión al sector privado progresiva). El sistema propio genera automáticamente:
- XML FacturaE con firma XAdES-EPES (requiere certificado digital del emisor)
- Integración con plataforma FACe para facturas a AAPP
- Envío vía email o portal cliente para facturas B2C
- Archivo durante 5 años (obligación legal)

**VeriFactu.** El sistema Verifactu (Real Decreto 1007/2023, en vigor desde enero 2026) obliga a los ISP a registrar cada factura en el Registro de Facturas de la AEAT antes de su emisión. El sistema propio integra con la API REST de la AEAT para registro en tiempo real o batch, gestiona los códigos QR de verificación que deben aparecer en cada factura, y mantiene el libro registro electrónico requerido.

### Reporting Calidad CNMC

La CNMC (Comisión Nacional de los Mercados y la Competencia) exige a los operadores con más de 100.000 líneas de banda ancha fija reportar indicadores de calidad de servicio trimestralmente. Para operadores regionales más pequeños, la obligación es menor, pero la normativa de transparencia de la CMT/CNMC afecta a todos — los ISP deben publicar las velocidades reales de su red.

Un sistema propio puede:
- Recoger métricas de calidad desde sondas activas (ICMP, iperf3 programado) en la red de acceso
- Correlacionar datos de calidad con reclamaciones abiertas en el mismo período
- Generar informes periódicos de velocidad real vs contratada para cumplir con el deber de información
- Preparar documentación para eventuales investigaciones CNMC con historial completo

### Portal de Autogestión Clientes

Alta online, cambio de tarifa, historial de facturas, pago de atrasos, ticketing de primer nivel. Reduce el 40–60% del volumen de llamadas al soporte para ISP con portal funcional. El portal debe gestionar autenticación segura (2FA vía SMS/TOTP) y cumplir el RGPD para consentimientos de marketing, portabilidad de datos, y derecho al olvido.

## Precios Reales 2026

**Foundation (28.000–48.000 €):** Facturación (SDD + tarjeta), integración FreeRADIUS vía SQL, portal clientes, suspensión automática morosos, FacturaE/VeriFactu, notificaciones email/SMS, reporting básico. Build: 12–18 semanas.

**Professional (55.000–80.000 €):** Todo el Foundation más API Mikrotik avanzada (QoS por cliente, multi-gateway), facturación por consumo para clientes empresariales, dashboard de calidad CNMC, sistema de ticketing integrado, integración monitorización de red (Zabbix/LibreNMS). Build: 18–26 semanas.

**Enterprise (85.000–110.000 €):** Todo el Professional más multi-sede/multi-región, app móvil técnicos (órdenes de trabajo, test conectividad in-situ), BI de ingresos y churn, exportación datos CNMC, gestión CPE (router cliente) de forma remota. Build: 26–36 semanas.

Infraestructura post-desarrollo: 500–2.000 €/mes (servidor dedicado o cluster VPS, API AEAT VeriFactu, SMS gateway, backups).

## FAQ

**¿Vale la pena desarrollar propio con 1.000 clientes?**
Con 1.000 clientes, Splynx cuesta 550–850 €/mes más el coste de un sistema FacturaE separado (80–200 €/mes). Infraestructura del sistema propio: 300–500 €/mes. Ahorro anual: 4.000–9.000 €. Un build de 45.000 € requiere 5–11 años solo para amortizarse en costes. El driver real para el desarrollo propio a 1.000 clientes es el cumplimiento normativo completo (FacturaE nativa, SDD SEPA correcto, VeriFactu integrado, RGPD) y la independencia del proveedor.

**¿Cómo gestiono la suspensión sin cortar clientes empresariales por error?**
Los clientes empresariales tienen un perfil de suspensión separado: periodo de gracia mayor (30 vs 7 días), cadena de notificaciones (email + intento de llamada telefónica antes de la suspensión), y flag de override manual que bloquea la suspensión automática para cuentas con incidencia activa en escalado. El motor de suspensión verifica el tipo de cuenta antes de cualquier acción.

**VeriFactu: ¿qué ocurre si el servicio AEAT no está disponible en el momento de facturar?**
VeriFactu permite modo offline con registro posterior en el plazo de 4 horas (operación asíncrona). El sistema propio mantiene una cola de facturas pendientes de registro, las reintenta automáticamente cuando la API AEAT responde, y alerta al operador si el tiempo de indisponibilidad supera el umbral legal. El código QR de verificación se genera localmente pero se completa con el hash AEAT cuando el registro confirma.

**¿Cómo funciona el SDD SEPA en la práctica?**
Tu entidad bancaria te asigna un Identificador de Acreedor (IA). Los mandatos SDD se firman digitalmente por los clientes al alta. El sistema genera ficheros XML PAIN.008 para cada ciclo de cobro y los transmite al banco con el preaviso requerido (D-5 para SDD Core, D-2 para SDD B2B). Las devoluciones R-transaction llegan como ficheros CAMT.054 — el sistema los procesa automáticamente y activa el flujo de recupero correspondiente por código.

**¿Qué ocurre si la base de datos cae durante autenticaciones PPPoE activas?**
FreeRADIUS tiene un modo `failsafe`: si no llega al backend SQL, puede rechazar todas las autenticaciones (fail-closed) o permitirlas todas (fail-open). Para los ISP, fail-open con alerta inmediata es preferible — una interrupción temporal no debe desconectar a todos los clientes. El sistema debe enviar alerta en 60 segundos tras la pérdida de contacto con la BD y tener failover automático en configuración HA.
