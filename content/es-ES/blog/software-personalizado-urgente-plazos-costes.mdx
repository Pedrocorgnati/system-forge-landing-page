# Software Personalizado Urgente: Qué Es Realista en 4–8 Semanas

Software personalizado con urgencia no significa software inestable. Significa **software con alcance brutalmente reducido**. Una función core — la que sin ella tu negocio no funciona — más autenticación y un panel admin básico: eso es lo que obtienes en 4–8 semanas por €7.000–€38.000. Todo lo demás es Fase 2. Las empresas que intentan construirlo todo urgentemente no entregan nada útil, o entregan algo tan inestable que cuesta más arreglarlo que rehacerlo desde cero.

## Qué Significa "Urgente" en el Desarrollo Custom

Urgente no es un mito — es un compromiso. Ganas velocidad renunciando a funcionalidad. Cada semana que añades al plazo, puedes añadir una funcionalidad significativa:

| Plazo | Qué es factible |
|-------|----------------|
| 2–3 semanas | Landing page con formulario, CMS básico, sin lógica backend |
| 4–6 semanas | Una función core + autenticación + admin básico |
| 6–10 semanas | Función core + 2 secundarias + pagos o integración |
| 3–4 meses | Producto completo con 5–8 funcionalidades, arquitectura propia, QA |

Cualquier promesa de "ERP completo en 3 semanas" es una plantilla precostruida con personalización cosmética, o la premisa de un desastre.

## El Alcance Mínimo para un Sistema Urgente

Para un sistema genuinamente útil y estable en menos de 8 semanas, se necesitan exactamente tres cosas:

**1. La función core que resuelve el problema**
Sé brutal. Si estás construyendo un sistema de gestión de obras, la función core es: crea obra → asigna al operario → operario marca completado. Todo lo demás (facturación, informes, notificaciones) es Fase 2.

**2. Autenticación con roles de usuario**
Todo sistema con más de una persona usando necesita auth. Define los roles de antemano: admin, usuario, visualizador. La confusión sobre roles descubierta en la semana 6 de 8 es un proyecto-killer.

**3. Un panel admin básico**
Alguien necesita gestionar los datos. Una interfaz admin de lectura/escritura — aunque esté sin estilo — evita que necesites un desarrollador cada vez que hay que corregir un registro.

## Costes Realistas (EUR, 2026)

| Alcance | Plazo | Coste |
|---------|-------|-------|
| Core + auth + admin básico | 4–6 sem. | €7.000–€17.000 |
| + Pagos (Stripe) | 6–8 sem. | €14.000–€26.000 |
| + App móvil (React Native) | 8–12 sem. | €23.000–€42.000 |
| Producto completo 5+ funcionalidades | 3–4 meses | €38.000–€95.000+ |

Costes **solo de desarrollo**. Añadir:
- Hosting: €20–€150/mes (Vercel, Railway)
- Mantenimiento: €500–€1.500/mes (corrección bugs, actualizaciones, soporte)
- Setup infraestructura: €500–€2.000 (una sola vez)

## Señales de Alerta al Contratar Desarrollo Urgente

**Señal 1: Sin fase de discovery**
Cualquier desarrollador que empiece a escribir código sin un discovery de 1–2 semanas (requisitos, wireframes, decisiones de arquitectura) va hacia un scope creep. El discovery es lo que separa un proyecto de 6 semanas de uno de 6 meses.

**Señal 2: Precio fijo con alcance abierto**
"Construimos todo tu sistema por €10.000" sin una lista definida de funcionalidades. Esto acaba en un producto a medias y una conversación difícil sobre "trabajos adicionales".

**Señal 3: Sin mención de deuda técnica**
Los proyectos urgentes toman atajos — ese es el trato. Los buenos desarrolladores documentan los atajos y señalan qué hay que abordar en la Fase 2. Quienes no mencionan esto o son ingenuos o están ocultando algo.

**Señal 4: Portfolio sin productos reales en producción**
Pide ver productos en producción, no mockups. Navega por ellos. Un desarrollador que ha entregado productos reales piensa de forma diferente a uno que solo entrega pruebas de concepto.

## Cómo Contratar para Desarrollo Urgente

1. **Escribe un documento de alcance de una página** — lista de funcionalidades, roles de usuario, integraciones necesarias, fecha límite
2. **Pide una propuesta técnica en 3 días** — no un presupuesto, una propuesta con: elección del stack y por qué, qué entra/sale del alcance, riesgos, hitos de pago
3. **Empieza con un sprint de discovery pagado** (€800–€2.500) — 1 semana de planificación arquitectónica, wireframes y spec detallada. Si el desarrollador se niega, cambia de desarrollador
4. **Define los criterios de aceptación antes de escribir una línea de código** — ¿qué significa "listo" para cada funcionalidad?
5. **Demos semanales, no mensuales** — ve el producto cada viernes

## Stack Tecnológico para la Velocidad

| Capa | Elección Rápida | Por qué |
|------|----------------|---------|
| Frontend | Next.js 15 (App Router) | Server components reducen el boilerplate |
| Base de datos | Supabase (PostgreSQL + realtime) | Auth + DB + storage en uno, setup inmediato |
| Auth | Supabase Auth o Clerk | Roles, social login, MFA en horas |
| Pagos | Stripe | Integración más rápida, documentación excelente |
| Hosting | Vercel + Supabase | Cero DevOps durante los primeros 6 meses |

Este stack no es correcto para cada proyecto — pero es la combinación más rápida que he encontrado para desarrollo custom urgente con un equipo pequeño.

## Expectativas Post-Lanzamiento

Los sistemas se rompen, especialmente en los primeros 30 días. Presupuesta 2–3 meses de soporte post-lanzamiento a €500–€1.000/mes. Esto es mantenimiento operativo normal, no un fallo:

- **Semanas 1–2:** bugs de casos límite que los tests no capturaron
- **Semanas 3–4:** pequeños ajustes UX pedidos por usuarios reales
- **Semanas 5–8:** primeras peticiones de funcionalidades de Fase 2

No confundas el soporte post-lanzamiento con fallos del desarrollo.

## FAQ

**¿Un freelancer puede entregar software urgente de forma fiable?**
Sí, para el alcance correcto. Un senior developer puede construir un alcance de 4–6 semanas bien definido de forma fiable. Para scope de más de 8 semanas con múltiples integraciones, un equipo pequeño (2–3 personas) reduce el riesgo considerablemente.

**¿Cuál es la diferencia entre una plantilla y software personalizado?**
Una plantilla está construida para todos — adaptas tu negocio a la plantilla. El software personalizado está construido para tu proceso específico. Las plantillas son 10x más rápidas y baratas; el personalizado es correcto cuando tu proceso es genuinamente único.

**¿Soy propietario del código después del desarrollo?**
Debes serlo. El contrato debe incluir propiedad total del código y entrega de fuentes. Evita desarrolladores que quieran alojar tu código en sus cuentas sin entrega.

**¿El desarrollo offshore es viable para plazos urgentes?**
El offshore puede ahorrar el 40–60% en coste pero añade overhead de coordinación — diferencias horarias, barreras de idioma, distintas expectativas de calidad. Para plazos urgentes (menos de 8 semanas), el nearshore o mismo huso horario suele valer el sobreprecio.

**¿Qué incluir en el contrato para desarrollo urgente?**
Un contrato bien estructurado protege a ambas partes: lista definida de funcionalidades con criterios de aceptación, cláusula de propiedad del código, entrega del repositorio con todo el historial git, documentación técnica (arquitectura, instrucciones de despliegue, lista de variables de entorno), términos de soporte post-lanzamiento, y proceso para cambios de alcance. Saltarse cualquiera de estos puntos genera fricciones al final del proyecto, cuando ambas partes están agotadas e intentando salir a producción.

**¿Cómo valido la demanda antes de gastar €7.000+?**
Antes de invertir en el build, valida que los clientes pagarán por tu función core: una landing page con lista de espera, un test "puerta falsa" con botón de compra, y al menos 5 entrevistas con potenciales clientes sobre su proceso actual. El peor resultado en software urgente es gastar €40.000 para construir rápido algo que nadie quiere.
