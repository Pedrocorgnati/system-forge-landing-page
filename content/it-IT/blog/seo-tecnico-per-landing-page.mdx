Un buon contenuto su un sito lento non si posiziona. Questa realta e diventata esplicita nel 2021, quando Google ha ufficializzato i Core Web Vitals come fattore di ranking. Prima di allora, il SEO tecnico veniva spesso trattato come un complemento — qualcosa che si faceva dopo aver il contenuto giusto. Ora, le prestazioni del server, la stabilita visiva della pagina durante il caricamento e la reattivita alle interazioni dell'utente sono metriche che influenzano direttamente la posizione nei risultati di ricerca.

Ma i Core Web Vitals sono solo uno strato del SEO tecnico. Ci sono altri elementi altrettanto critici che la maggior parte delle landing page ignora: Schema.org per i rich snippet, la gestione corretta dei canonical tag nelle pagine con varianti multiple, la crawlability garantita affinche Googlebot indicizzi correttamente e — quando applicabile — gli hreflang per i siti multilingue.

## Core Web Vitals: LCP, CLS e INP nella Pratica

I tre Core Web Vitals misurano dimensioni diverse dell'esperienza utente:

**LCP (Largest Contentful Paint)** misura il tempo fino a quando l'elemento visibile piu grande nella parte sopra la piega viene renderizzato. Nella pratica, di solito e l'immagine hero o il blocco del titolo. L'obiettivo e sotto i 2,5 secondi.

Le cause piu comuni di un LCP elevato nelle landing page:

- Immagine hero in formato PNG o JPEG senza ottimizzazione (usa WebP o AVIF)
- Immagine hero senza `fetchpriority="high"` — il browser la tratta come risorsa secondaria
- CSS o JavaScript di terze parti che bloccano il rendering prima dell'LCP
- Assenza di CDN, con l'asset servito dal server di origine

```html
<!-- Immagine hero con priorita corretta -->
<img
  src="/hero.png"
  alt="Descrizione dell'immagine"
  width="1200"
  height="630"
  fetchpriority="high"
  loading="eager"
/>
```

**CLS (Cumulative Layout Shift)** misura l'instabilita visiva — elementi che si spostano mentre la pagina si carica. L'obiettivo e sotto lo 0,1.

I maggiori responsabili del CLS sono le immagini senza dimensioni definite (il browser non riserva lo spazio prima del caricamento), i font web che causano FOUT (Flash of Unstyled Text) e i banner dei cookie che appaiono dopo che il layout e gia stato renderizzato.

**INP (Interaction to Next Paint)** ha sostituito l'FID a marzo 2024. Misura la latenza di risposta a qualsiasi interazione dell'utente (clic, tocco, tasto) durante l'intera sessione. L'obiettivo e sotto i 200ms. La causa principale di un INP elevato e il JavaScript pesante nel main thread, specialmente da librerie di analytics e widget di chat.

## Schema.org: Rich Snippet che Aumentano il CTR

Schema.org e un vocabolario di dati strutturati che Google usa per comprendere il contenuto della pagina e, in alcuni casi, mostrare rich snippet nei risultati di ricerca. I rich snippet aumentano il CTR senza migliorare direttamente il ranking — ma piu clic con la stessa posizione e un risultato prezioso.

Per le landing page di servizi, gli schema piu rilevanti sono:

```json
{
  "@context": "https://schema.org",
  "@type": "Service",
  "name": "Sviluppo Landing Page",
  "description": "Landing page in Next.js con focus su performance e conversione",
  "provider": {
    "@type": "Organization",
    "name": "SystemForge",
    "url": "https://systemforge.dev"
  },
  "areaServed": "IT",
  "hasOfferCatalog": {
    "@type": "OfferCatalog",
    "name": "Piani",
    "itemListElement": [
      {
        "@type": "Offer",
        "itemOffered": {
          "@type": "Service",
          "name": "Landing Page Starter"
        },
        "price": "2500",
        "priceCurrency": "EUR"
      }
    ]
  }
}
```

Per le pagine FAQ (sezione comune nelle landing page), lo schema `FAQPage` genera la visualizzazione di domande e risposte direttamente nei risultati di ricerca, aumentando lo spazio occupato nella SERP:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Quanto tempo serve per sviluppare una landing page?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Tra 5 e 10 giorni lavorativi a seconda della complessita e dell'approvazione dei contenuti."
      }
    }
  ]
}
```

Valida l'implementazione con il Rich Results Test di Google prima di pubblicare.

## Canonical Tag e Contenuto Duplicato

Il contenuto duplicato e un problema frequente nelle landing page che hanno varianti per UTM, varianti di copy per traffico a pagamento rispetto a organico, o versioni della stessa pagina su domini multipli.

Il canonical tag comunica a Google qual e l'URL "vera" di una pagina, consolidando il link equity di tutte le varianti in un unico URL:

```html
<!-- Su tutte le varianti della landing page -->
<link rel="canonical" href="https://tuosito.it/landing-page-servizio" />
```

Situazioni che richiedono il canonical tag nelle landing page:

- URL con parametri UTM che vengono indicizzati (`/lp?utm_source=google`)
- Stesso contenuto accessibile su `www.tuosito.it` e `tuosito.it`
- Versioni di test con slug diverso dalla versione principale
- Landing page duplicate per regioni diverse senza hreflang configurato

L'errore piu comune e non configurare il canonical tag nelle pagine raggiunte tramite parametri UTM. Google non ignora i parametri UTM automaticamente — se l'URL con parametri e indicizzabile, puo essere interpretata come contenuto duplicato.

## Crawlability: Robots.txt, Sitemap e Indicizzazione Forzata

**Robots.txt** controlla quali URL Googlebot puo esplorare. L'errore classico e bloccare accidentalmente CSS e JavaScript necessari per renderizzare la pagina correttamente — Google deve renderizzare il JavaScript per indicizzare le SPA e le pagine con contenuto dinamico.

Un robots.txt corretto per i siti Next.js:

```txt
User-agent: *
Allow: /
Disallow: /api/
Disallow: /_next/

Sitemap: https://tuosito.it/sitemap.xml
```

**Sitemap.xml** deve elencare tutti gli URL che vuoi indicizzati, con il tag `<priority>` regolato per riflettere l'importanza relativa. Le landing page principali devono avere priorita `1.0`, le pagine secondarie `0.8` e le pagine di supporto (informativa sulla privacy, termini) `0.3`.

**Indicizzazione forzata:** quando pubblichi una nuova landing page e vuoi che Google la indicizzi rapidamente, usa Google Search Console, Controllo URL e Richiesta indicizzazione. Il processo richiede da alcune ore a 3 giorni. Per le landing page con campagne a pagamento attive, inviare l'URL per l'indicizzazione appena pubblicato e essenziale — una landing page nuova non ancora indicizzata puo impiegare settimane per apparire nei risultati organici.

Lo strumento **Controllo URL** in Search Console rivela anche i problemi di crawl: se Googlebot sta incontrando errori di reindirizzamento, se la versione renderizzata da Googlebot differisce da cio che l'utente vede (indicando un blocco del JavaScript), o se il canonical tag viene rispettato.

## Conclusione

Il SEO tecnico non e facoltativo per le landing page che dipendono dal traffico organico. Prestazioni sotto le soglie dei Core Web Vitals, assenza di dati strutturati, canonical tag mal configurati e problemi di crawlability sono lacune che il miglior contenuto del mondo non compensa.
