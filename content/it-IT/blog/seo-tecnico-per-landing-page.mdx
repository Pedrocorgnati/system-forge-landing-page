Un buon contenuto su un sito lento non rankeggia. Questa realtà è diventata esplicita nel 2021, quando Google ha ufficialmente inserito i Core Web Vitals come fattore di ranking. Prima di allora, il SEO tecnico era spesso trattato come un complemento — qualcosa da fare dopo aver creato il contenuto giusto. Oggi, la performance del server, la stabilità visiva della pagina durante il caricamento e la reattività alle interazioni dell'utente sono metriche che impattano direttamente la posizione nei risultati di ricerca.

Ma i Core Web Vitals sono solo uno strato del SEO tecnico. Ci sono altri elementi ugualmente critici che la maggior parte delle landing page ignora: Schema.org per i rich snippet, corretta gestione dei canonical tag in pagine con più variazioni, crawlability garantita affinché Googlebot indicizzi correttamente, e — quando applicabile — hreflang per siti multilingue.

## Core Web Vitals: LCP, CLS e INP nella Pratica

I tre Core Web Vitals misurano dimensioni diverse dell'esperienza utente:

**LCP (Largest Contentful Paint)** misura il tempo fino al rendering del più grande elemento visibile nel viewport superiore. In pratica, di solito è l'immagine hero o il blocco headline. L'obiettivo è sotto i 2,5 secondi.

Le cause più comuni di LCP elevato nelle landing page:

- Immagine hero in formato PNG o JPEG senza ottimizzazione (usa WebP o AVIF)
- Immagine hero non contrassegnata con `fetchpriority="high"` — il browser la tratta come risorsa secondaria
- CSS o JavaScript di terze parti che bloccano il rendering prima dell'LCP
- Assenza di CDN, con l'asset servito dal server di origine

```html
<!-- Immagine hero con priorità corretta -->
<img
  src="/hero.png"
  alt="Descrizione dell'immagine"
  width="1200"
  height="630"
  fetchpriority="high"
  loading="eager"
/>
```

**CLS (Cumulative Layout Shift)** misura l'instabilità visiva — elementi che si spostano mentre la pagina si carica. L'obiettivo è sotto 0,1.

I principali responsabili del CLS sono immagini senza dimensioni definite, font web che causano FOUT (Flash of Unstyled Text) e banner di consenso cookie che appaiono dopo che il layout è già stato renderizzato.

**INP (Interaction to Next Paint)** ha sostituito l'FID a marzo 2024. Misura la latenza di risposta a qualsiasi interazione dell'utente (clic, tocco, tasto) durante l'intera sessione. L'obiettivo è sotto i 200ms. La causa principale di INP elevato è JavaScript pesante nel main thread, specialmente da librerie di analytics e widget di chat.

## Schema.org: Rich Snippet che Aumentano il CTR

Schema.org è un vocabolario di dati strutturati che Google usa per comprendere il contenuto della pagina e, in alcuni casi, mostrare rich snippet nei risultati di ricerca. I rich snippet aumentano il CTR senza migliorare direttamente il ranking — ma più clic con la stessa posizione è un risultato prezioso.

Per le landing page di servizi, gli schema più rilevanti sono:

```json
{
  "@context": "https://schema.org",
  "@type": "Service",
  "name": "Sviluppo Landing Page",
  "description": "Landing page in Next.js con focus su performance e conversione",
  "provider": {
    "@type": "Organization",
    "name": "SystemForge",
    "url": "https://systemforge.dev"
  },
  "areaServed": "IT",
  "hasOfferCatalog": {
    "@type": "OfferCatalog",
    "name": "Piani",
    "itemListElement": [
      {
        "@type": "Offer",
        "itemOffered": {
          "@type": "Service",
          "name": "Landing Page Starter"
        },
        "price": "2000",
        "priceCurrency": "EUR"
      }
    ]
  }
}
```

Per le pagine FAQ (sezione comune nelle landing page), lo schema `FAQPage` genera la visualizzazione di domande e risposte direttamente nei risultati di ricerca, aumentando lo spazio occupato nel SERP:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Quanto tempo richiede lo sviluppo di una landing page?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Tra 5 e 10 giorni lavorativi in base alla complessità e all'approvazione dei contenuti."
      }
    }
  ]
}
```

Valida l'implementazione con il Rich Results Test di Google prima di pubblicare.

## Canonical Tag e Duplicate Content

Il duplicate content è un problema frequente nelle landing page con variazioni per UTM, variazioni di copy per traffico a pagamento rispetto a quello organico, o versioni della stessa pagina su più domini.

Il canonical tag informa Google su quale sia l'URL "vera" di una pagina, consolidando il link equity di tutte le variazioni in un'unica URL:

```html
<!-- In tutte le variazioni della landing page -->
<link rel="canonical" href="https://tuosito.com/landing-page-servizio" />
```

Situazioni che richiedono il canonical tag nelle landing page:

- URL con parametri UTM che vengono indicizzati (`/lp?utm_source=google`)
- Stesso contenuto accessibile su `www.tuosito.com` e `tuosito.com`
- Versioni di test con slug diverso dalla versione principale
- Landing page duplicate per regioni diverse senza hreflang configurato

L'errore più comune è non configurare il canonical tag nelle pagine accessibili tramite parametri UTM. Google non ignora automaticamente i parametri UTM — se l'URL con parametri è indicizzabile, può essere interpretata come contenuto duplicato.

## Crawlability: Robots.txt, Sitemap e Indicizzazione Forzata

**Robots.txt** controlla quali URL il Googlebot può scansionare. L'errore classico è bloccare accidentalmente CSS e JavaScript necessari per renderizzare correttamente la pagina — Google ha bisogno di renderizzare il JavaScript per indicizzare SPA e pagine con contenuto dinamico.

Un robots.txt corretto per siti Next.js:

```txt
User-agent: *
Allow: /
Disallow: /api/
Disallow: /_next/

Sitemap: https://tuosito.com/sitemap.xml
```

**Sitemap.xml** deve elencare tutti gli URL che vuoi indicizzati, con il tag `<priority>` adattato per riflettere l'importanza relativa. Le landing page principali devono avere priorità `1.0`, le pagine secondarie `0.8`, e le pagine di supporto `0.3`.

**Indicizzazione forzata:** quando pubblichi una nuova landing page e vuoi che Google la indicizzi rapidamente, usa Google Search Console → URL Inspection → Request Indexing. Il processo richiede da alcune ore a 3 giorni.

Lo strumento **URL Inspection** in Search Console rivela anche problemi di crawl: se Googlebot trova errori di reindirizzamento, se la versione renderizzata da Googlebot differisce da quella dell'utente, o se il canonical tag viene rispettato.

## Conclusione

Il SEO tecnico non è opzionale per le landing page che dipendono dal traffico organico. Performance al di sotto degli obiettivi dei Core Web Vitals, assenza di dati strutturati, canonical tag mal configurati e problemi di crawlability sono lacune che il miglior contenuto del mondo non compensa.

Il vantaggio di sviluppare landing page con Next.js è che gran parte di questo SEO tecnico è incluso per impostazione predefinita: l'esportazione statica elimina l'TTFB elevato, il componente `next/image` risolve automaticamente LCP e CLS per le immagini, e la generazione della sitemap può essere automatizzata.
