# Integrar Shopify com ERP e Fiscal Brasileiro: Custo, APIs e Armadilhas em 2026

O Shopify não emite NF-e nativamente no Brasil em 2026 — isso é uma limitação conhecida e crítica para lojistas brasileiros. A integração com ERPs como Bling (R$ 46-220/mês) ou Omie para emissão fiscal custa entre R$ 8.000 e R$ 25.000 em desenvolvimento de API customizada, dependendo do volume de pedidos e complexidade tributária. Para quem vende mais de 30 pedidos/dia, emissão manual é inviável. Neste guia, detalho cada opção com custo real e as armadilhas que todo lojista Shopify no Brasil enfrenta antes de colocar dinheiro em qualquer integração.

*Por Pedro Corgnati — desenvolvedor com dezenas de integrações Shopify + ERP fiscal no mercado brasileiro.*

## Por que o Shopify não emite NF-e nativamente no Brasil (e o que fazer)

O Shopify é uma plataforma americana desenhada para o mercado global. O sistema tributário brasileiro — com NF-e, SPED, CFOP, CST, Substituição Tributária — é suficientemente complexo para que a plataforma opte por não implementar o módulo fiscal diretamente. Em vez disso, a estratégia da Shopify para o Brasil é:

1. **Shopify App Store:** apps de terceiros para NF-e (eNotas, NFe.io, Notazz)
2. **Webhooks + API:** eventos de pedido disponíveis via API para integração com ERPs

O problema dos apps da App Store é que são genéricos. Funcionam para casos simples (produto físico, tributação padrão), mas falham quando você tem:
- Substituição Tributária (ST) por produto e por estado de destino
- Operações interestaduais com CFOP variável (5.102 vs 6.102)
- Produtos com alíquota de IPI ou pauta aduaneira
- Shopify Markets (venda para outros países com CFOP de exportação)

Para esses casos, integração via API customizada com ERP é o único caminho.

**Quando usar app:** volume abaixo de 50 pedidos/dia, produtos sem ST, tributação simples (Simples Nacional ou Lucro Presumido padrão).

**Quando não usar app:** ST, CFOP variável por estado, mais de 200 pedidos/dia (apps têm limite de requisições), necessidade de reconciliação fiscal integrada com ERP.

| Nível | O que inclui | Investimento | Prazo |

## As opções de integração: Bling, Omie, TOTVS e solução própria

### Bling

**Quando indicar:** loja pequena/média, Simples Nacional, sem ST complexa, integração direta via API REST documentada.

- API REST com webhooks: documentação pública, estável
- Plano mínimo para API: R$ 161/mês (Pequeno)
- Limitação: Rate limit de 2 req/segundo — crítico para lojas com pico de pedidos
- NF-e emitida em lote ou unitária: ambas disponíveis

**Padrão de integração que usamos:**
```
Shopify webhook (order/paid) → 
  Serviço de integração (validação + enriquecimento) → 
  Bling API (criar pedido + gerar NF-e) → 
  Shopify (atualizar metafield com número da NF-e)
```

### Omie

**Quando indicar:** PMEs com contabilidade integrada, Lucro Presumido, necessidade de conciliação contábil além de NF-e.

- API SOAP (antiga) e REST (nova): ambas disponíveis
- Custo: R$ 149-899/mês dependendo do módulo
- Vantagem: módulo contábil integrado — NF-e já entra no razão automaticamente
- Desvantagem: API mais complexa que Bling; curva de desenvolvimento maior

### TOTVS

**Quando indicar:** PMEs com TOTVS já contratado que precisam de canal de vendas online.

- API REST disponível (módulo de integração pago separado)
- Custo de integração customizada: R$ 15.000-25.000 além do desenvolvimento web
- Vantagem: ST e CFOP muito bem implementados no módulo fiscal do TOTVS
- Desvantagem: custo mensal alto (R$ 500-2.500 só pelo TOTVS)

### Solução própria de emissão

Para lojas com 500+ pedidos/dia, desenvolver motor próprio de NF-e usando APIs diretas da SEFAZ pode sair mais barato no longo prazo.

| Abordagem | Custo setup | Custo/NF-e | Break-even vs. app |
|-----------|------------|------------|-------------------|
| App (eNotas Pro) | R$ 0 | R$ 0,75-1,50 | — |
| Motor próprio | R$ 35.000-50.000 | R$ 0,02-0,05 | ~3.000 NFs/mês |

## Armadilhas técnicas ao integrar Shopify com fiscal brasileiro

### 1. CFOP errado nas vendas interestaduais

O CFOP (Código Fiscal de Operações e Prestações) varia por estado de origem × estado de destino, tipo de produto e se é venda para consumidor final ou revendedor.

**Armadilha:** Shopify não captura CNPJ do comprador no checkout padrão. Sem CNPJ, não dá para saber se é consumidor final ou revendedor — e o CFOP muda. Solução: campo customizado no checkout (Shopify Plus) ou validar via CNPJ na integração.

### 2. Substituição Tributária por estado de destino

ST é calculada pelo estado de destino do produto. Um mesmo produto pode ter ST em SP mas não ter em MG. Sistemas de integração que não implementam tabela de ST por produto × estado vão emitir NF-e sem o valor correto de ICMS-ST — gerando autuação.

**Solução:** manter tabela de NCM × estado × alíquota ST atualizada no serviço de integração, com versionamento por data de vigência.

### 3. Falha silenciosa na emissão

A SEFAZ pode rejeitar a NF-e por schema inválido, NCM incorreto, série bloqueada ou certificado digital expirado. Apps genéricos frequentemente falham silenciosamente — o pedido aparece como "NF-e emitida" no Shopify mas na realidade foi rejeitada.

**Solução obrigatória:** sempre implementar webhook de retorno do ERP confirmando número de protocolo SEFAZ. Se não vier protocolo em 5 minutos, disparar alerta para equipe fiscal.

### 4. Certificado digital A1 expirando

O certificado digital A1 (arquivo .pfx) expira em 1 ano. Integração que não monitora expiração vai parar de emitir NF-e de surpresa.

**Checklist anti-armadilha:**
- Monitor de expiração de certificado com alerta 30 dias antes
- Teste de emissão em staging a cada deploy
- Log de cada tentativa de emissão com timestamp e protocolo SEFAZ
- Retry automático em caso de timeout (SEFAZ tem instabilidade conhecida)
- Dashboard de status de NFs por pedido visível para equipe de operações

## Perguntas Frequentes sobre Shopify e fiscal brasileiro

**O Shopify vai implementar NF-e nativamente algum dia?**
Até 2026, não há sinalização oficial da Shopify. A empresa cresce no Brasil mas a complexidade tributária BR é alta o suficiente para a estratégia continuar sendo via parceiros e apps. Para quem precisa de NF-e hoje, integração via ERP é o caminho mais confiável.

**App da App Store ou integração customizada?**
App funciona para: Simples Nacional, produto sem ST, sem Shopify Markets, até 100 pedidos/dia. Integração customizada é necessária quando qualquer um desses pontos falha — especialmente ST, que os apps geralmente não implementam corretamente para todos os estados.

**Qual ERP é melhor para integrar com Shopify?**
Para lojas menores (Simples Nacional, sem ST): Bling tem API mais simples e documentação melhor. Para PMEs com Lucro Presumido e necessidade de contabilidade integrada: Omie. Para empresas com TOTVS já contratado: TOTVS direto, apesar de custo maior.

**Quanto tempo leva a integração?**
Integração básica (Shopify → Bling → NF-e): 3-5 semanas com equipe experiente. Integração com ST complexa e painel de monitoramento: 6-10 semanas. Nunca confie em promessa de "integração em 1 semana" — implica que ST não foi tratada.

**O que acontece se a NF-e for rejeitada pela SEFAZ?**
A venda aconteceu, mas a NF-e não existe legalmente. Você precisa cancelar o pedido fiscalmente, corrigir o erro e re-emitir. Sem monitoramento de retorno do protocolo SEFAZ, você pode ter centenas de pedidos sem NF-e válida sem saber — e descobrir só na auditoria fiscal.

**Posso emitir NF-e manualmente acima de 30 pedidos/dia?**
Matematicamente sim, mas operacionalmente não. Uma emissão manual leva 3-5 minutos. Com 50 pedidos/dia, são 2,5-4h/dia de trabalho fiscal. Com 200 pedidos/dia (como na Black Friday), é humanamente impossível.
